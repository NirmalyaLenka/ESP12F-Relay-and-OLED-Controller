Room Control

A local, cloud-free web panel and OLED status display for four relay-switched loads, with built-in delay timers and no app to install.

NodeMCU 1.0 / ESP‑12F SSD1306 128×64 OLED 4-Channel Relay Local Web Server EEPROM Persisted
01

Overview

This firmware turns a NodeMCU into a self-contained switch box for four loads — named Fan, Light, PC, and Night by default, but that's just a label change away from anything else. It serves its own control panel over HTTP, so any phone or laptop on the same WiFi network can open the board's IP address and get a dark-themed page with a toggle and a delay-timer form for each channel.

There's no cloud dependency and no companion app — the whole interface is a single HTML page embedded in flash memory. An attached OLED mirrors the same state locally: clock, per-channel status, and a small WiFi indicator.

4 Relay Channels

Independently toggled, each with its own name and state, persisted across power loss.

Delay Timers

Schedule a channel to switch ON or OFF after N minutes — survives a closed browser tab.

OLED Status

Live clock, per-channel state, a 2×2 activity indicator, and a WiFi connection dot.

Dual Time Sync

NTP when available, with the browser pushing its own clock as a fallback every 5 minutes.

Hardware & Pinout

Built against a NodeMCU 1.0 (ESP‑12F), an I2C SSD1306 OLED at address 0x3C, and 4 relay modules. Pins are set with #defines at the top of the sketch if yours differ.

FunctionGPIONodeMCU Label
OLED SDAGPIO4D2
OLED SCLGPIO5D1
Relay 1 — FanGPIO16D0
Relay 2 — LightGPIO14D5
Relay 3 — PCGPIO12D6
Relay 4 — NightGPIO13D7
!

The relay boards this targets are active-LOW at the coil, but loads are wired through the NC contact rather than NO — so from the firmware's side, pin HIGH is what leaves the load powered (LOAD_ON is defined as HIGH). Using active-HIGH relays or NO wiring instead? Flip the LOAD_ON/LOAD_OFF defines, or every switch will act backwards.

03

Getting It Flashed

  1. Add the ESP8266 board package in Arduino IDE → Boards Manager URL: http://arduino.esp8266.com/stable/package_esp8266com_index.json
  2. Install Adafruit GFX Library and Adafruit SSD1306 via Library Manager. EEPROM, Wire, ESP8266WiFi, and ESP8266WebServer ship with the board package.
  3. Board settings: NodeMCU 1.0 (ESP‑12E Module), default flash size, 115200 upload speed.
  4. Set your ssid and password near the top of the sketch, then upload.
  5. Open Serial Monitor at 115200 baud on first boot to read the assigned IP address.
i

WiFi credentials are currently hardcoded in the sketch. Fine for a private repo — if this is going public, pull them into a small secrets.h that you .gitignore and #include instead.

04

Using It

Open http://<board-ip>/ from any device on the same network. Each channel is a card with a toggle switch and a timer form: enter minutes, choose ON or OFF, hit Set. The page polls the board once a second, shows a live countdown for any pending timer, and lets you cancel one with the red X.

The OLED mirrors the same state on the device itself: clock at the top, each channel's name and status below, an asterisk next to a channel with a timer pending, a filled/outline quadrant graphic for at-a-glance status, and a dot bottom-right — filled when WiFi is connected, hollow when it isn't.

Storage layout

State lives in one ConfigStore struct in EEPROM: a magic number (0xC0FFEE89) to detect a blank chip, the current state of all 4 channels, and up to one pending timer per channel (target time, action, active flag). Every change is committed immediately.

06

Worth Knowing

  • No authentication — anyone on the WiFi network can control the relays. Fine for a home LAN, don't expose this to the open internet as-is.
  • One timer per channel — setting a new one overwrites whatever was pending.
  • Missed timers catch up on reboot — if power was lost past a timer's target time, it fires as soon as the clock re-syncs, even if that's later than intended.
  • Plain HTTP, no encryption.
